## What broke — the two filed findings

**MISCHIEF-DF-71 (P3)** — `serve` has no single-owner guard on a run dir. A second
`mischief serve --dir RUN` started while the first daemon (pid 3147786) was live came up
normally: banner, no refusal, no warning. Its child was pid 3208558. One second later
`health.json` carried `pid: 3208558` while the hold `bf4a22b73b389339` had just been reverted at
ts 1793139969 by `own_pid=3147786` — the first daemon. health.json's `pid` is last-writer-wins
between two live daemons, so the product's only ownership signal can name a process that did not
perform the revert; an operator who supervises that pid can stop the wrong watchdog while the
other keeps reverting TTLs, and no surface reveals a duplicate daemon. Honest limit: **no double
revert was observed** — each hold got exactly one `ttl_expiry` proof row, so the duplicate-race
hazard is plausible but not demonstrated; only the identity/last-writer behaviour is.

Reproduce:
```sh
serve --dir RUN            # daemon A (capture its child pid)
serve --dir RUN            # daemon B, same dir -> no refusal
arm --fault S-001 --target scratch:W --ttl 15s --inverse-kind restore-file ... --dir RUN
printf 'LANDED' > W/f.toml
jq .pid RUN/health.json          # names one daemon
jq -r 'select(.type=="revert_proof")|.own_pid' RUN/reverter.jsonl   # names the other
```

**MISCHIEF-DF-72 (P4)** — `version` silently swallows every argument. `version --json`,
`version --nope`, `version -h`, `version --help` and `version junk` all return **rc=0** with the
identical plain line `mischief 5ecc160e7fb4`, while every other verb refuses an unknown flag
(`revert --all --json`, `retention --dry-run --json`, `battery --json`, `sim --json` -> rc=2
`flag provided but not defined`), an unknown verb (`statu`, `reverts` -> rc=2) and a malformed
value (`--ttl 30` -> rc=2). So `mischief version --json | jq -r .version` reports CLI success
with a payload jq cannot parse. Same surface, adjacent: the bare-`mischief` usage banner (the
only help, since every subcommand's `--help` exits 2 — open MISCHIEF-CLI-001) lists `[--json]`
for plan/doctor/audit but omits it on the status line, although PRD 6.1 documents
`mischief status [--all] [--dir D] [--json]` and the flag works.
